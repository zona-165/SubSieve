# SubSieve

订阅清洗网关 + 可视化管理后台，Docker Compose 一键部署。

订阅请求先经过黑名单、云厂商 IP 识别、UA、Token 和速率限制等多层拦截，通过后才反代到机场后端，防止订阅链接被扫描或滥用。

## 首次部署

### 前置要求

- 一台有公网 IP 的 VPS（Debian/Ubuntu 最低1c0.5g）
- 已安装 Docker + Docker Compose
- `80`、`64444` 以及计划使用的网关端口未被其他服务占用
- 如需自动申请 SSL 证书：提前把域名解析到本机（A 记录）

### 一键部署

```bash
git clone https://github.com/zona-165/SubSieve.git
cd SubSieve/sgw
./setup.sh
```

如果系统提示 `Permission denied`，再执行一次 `chmod +x setup.sh update.sh` 后重试即可。

向导会依次询问：

| 提示 | 说明 |
|------|------|
| 机场地址 | 你的机场面板域名，如 `panel.example.com`，不含 `https://` |
| 订阅路径 | 默认 `/api/v1/client/subscribe`，直接回车即可 |
| 订阅端口 | 机场后端监听端口，默认 `443` |
| 网关端口 | 客户端订阅链接对外暴露的端口，默认 `443` |
| 域名（SSL） | 输入已解析到本机的域名，脚本自动调用 acme.sh 申请证书；留空则手动放证书 |

部署脚本会等待 gateway 和 admin 均通过健康检查后再报告成功。访问信息会打印在终端，同时保存到 `DEPLOY_INFO.txt`。

## 食用方法
部署完成后，将原订阅链接中的域名和端口替换为部署了本项目的域名和端口即可。
```
示例：
# 原订阅链接
https://aaaa.bbbb.com:11111/api/v1/client/subscribe?token=xxxxxxxxxxxxxxxxxxxxxxx

# 替换为
https://your-domain.com:端口/api/v1/client/subscribe?token=xxxxxxxxxxxxxxxxxxxxxxx
```

## 套 AxisNow CDN 时获取真实客户端 IP

如果订阅域名前套了 AxisNow CDN，需要在 AxisNow 侧启用真实客户端 IP 传递，并在 SubSieve 侧只信任 AxisNow Edge/EIP。否则 nginx 的 `$remote_addr` 会是 AxisNow 回源 IP，日志、云 IP 判断、黑白名单和速率限制都会按 CDN IP 生效。

首次部署时，`setup.sh` 会询问 `AxisNow Edge/EIP`，填入 AxisNow 面板中 Edge/EIP 列表里的回源地址，多个用英文逗号分隔：

```env
AXISNOW_TRUSTED_IPS=1.2.3.4,5.6.7.8
REAL_IP_HEADER=X-Forwarded-For
```

已部署用户可直接在 `sgw/.env` 追加上述配置，然后重建：

```bash
cd SubSieve/sgw
docker compose up -d --build
```

验证配置是否进入容器：

```bash
docker exec subscribe-gateway nginx -T | grep -E "set_real_ip_from|real_ip_header|real_ip_recursive"
docker exec subscribe-gateway tail -n 20 /var/log/subscribe/access.log
```

如果日志第一列仍是 AxisNow IP，请确认 `AXISNOW_TRUSTED_IPS` 填的是 SubSieve 当前看到的 AxisNow 回源 IP；如果 AxisNow 只传 `X-Real-IP`，将 `REAL_IP_HEADER` 改为 `X-Real-IP` 后重建。

## 后续更新

已部署的用户，直接运行：

```bash
cd SubSieve/sgw
./update.sh
```

脚本会自动 git pull 最新代码、保留 `.env`、重新构建容器，并等待两个服务通过健康检查。若 nginx、PHP-FPM 或共享存储异常，脚本会打印容器日志并以非零状态退出，避免把启动失败误报为更新成功。

> **注意**：如果在后台修改了**网关端口**，需要在宿主机执行一次 `./update.sh` 才能让新端口生效（`.env` 中的 `GATEWAY_PORT` 由该脚本同步更新）。

如果你是从原仓库 `Null404-0/SubSieve` 部署的旧实例，先把远端切到本维护仓库：

```bash
cd SubSieve
git remote set-url origin https://github.com/zona-165/SubSieve.git
git pull origin main
cd sgw
./update.sh
```

## 访问后台

```
https://你的域名或IP:64444/<随机路径>
```

路径和账号密码见 `DEPLOY_INFO.txt`，或查看 `.env` 中的 `ADMIN_SECRET_PATH` / `ADMIN_PASS`。

后台会话 Cookie 默认启用 `Secure`、`HttpOnly` 和 `SameSite=Strict`，登录成功后会更换 Session ID。所有页面和 API 都必须先经过 Secret Path 路由，不能绕过隐藏路径直接执行 PHP 接口。

### 安全状态与观察规则

风险分析中的风险复核默认采用**只观察、人工复核**模式；阈值统一在「防护策略」中配置。后台每分钟依次预热统计与 `guard_cache.json`，从设置中的订阅路径计算以下规则：

- 单 IP 今日累计拉取次数，默认 `100`
- 单 IP 每分钟拉取次数，默认 `30`
- 单 Token 每分钟拉取次数，默认 `20`
- 单 Token 每小时不同来源 IP，默认 `8`
- 单 IP 每小时不同 Token，默认 `20`
- 单 IP 五分钟订阅入口 404，默认 `40`

风险项可标记为“待复核 / 持续观察 / 判定可信 / 确认异常”，判断保存在 `guard_reviews.json`。人工状态本身不会封禁；只有管理员明确点击封禁或进入名单页面添加规则才会改变网关行为。显式 IP 白名单不会进入行为风险队列。安全状态接口只返回 HMAC 指纹化 Token，不在新增的总览和复核数据中返回 Token 明文。

旧版 Top IP、Top Token、UA 排行和 `/24` 用户画像已从风险分析移除：这些内容与拉取记录重复，且没有独立的判断和处置闭环。拉取记录仍保留每个 IP 的请求总数、`200/403/429/444` 分布与多源 IP 情报；达到今日阈值后会自动进入“高频拉取”风险队列。

### AI 风险研判

AI 功能默认关闭，可在后台「系统设置 → AI 风险研判」中自行启用并填写 API Token。内置 OpenAI、DeepSeek、通义千问、Kimi、智谱、硅基流动、OpenRouter、Anthropic Claude、Google Gemini 和自定义接口预设，适配 OpenAI-compatible Chat Completions、Anthropic Messages 与 Gemini `generateContent` 三类协议。模型名称和 API 地址均可编辑，因此也可接入遵循相同协议的私有网关。

- **人工决策边界**：AI 只输出风险等级、置信度、关键证据、可能误报、复核建议和拟议动作，并强制标记为需要人工复核；它没有封禁 IP、暂停 Token、修改规则或删除数据的权限。
- **最小化发送**：默认不发送来源 IP 和 UA，只发送请求路径及汇总后的风险证据；管理员可分别开关这些字段。原始订阅 Token 永不发送，Token 只以已有 HMAC 指纹或再次 HMAC 化的别名进入分析。
- **密钥隔离**：API Token 仅写入服务器数据卷 `/etc/nginx/subscribe/ai_settings.json`，文件权限为 `0600`。设置接口只返回“是否已保存”，不会回显 Token；连接错误、分析结果和导出数据也会过滤密钥。
- **自动研判**：可单独开启后台定时分析并配置间隔和每次最多处理数量。维护任务每分钟触发一次检查，实际请求受配置间隔和冷却时间控制；最近结果保存在 `/etc/nginx/subscribe/ai_analysis.json`。
- **自定义接口**：选择“自定义兼容接口”后，可指定 OpenAI-compatible、Anthropic 或 Gemini 协议，再填写 HTTPS API 地址和模型名称。为防止密钥误发，系统拒绝 HTTP 明文地址。

建议先保存厂商、模型和 API 地址，再使用「测试连接」确认接口返回有效结构，最后开启自动分析。测试连接不会改变风险规则，也不会执行任何网关处置。

### Token 拉取限制

「防护策略」提供独立的 Token 拉取限制，默认规则为：

- 24 小时内最多出现 `10` 个不同来源 IP
- 每分钟最多拉取 `10` 次
- 超限后暂停该 Token `24` 小时

功能默认开启统计、关闭自动暂停。监控模式会显示活跃 Token、最高 IP 用量、每分钟峰值和模拟超限数量，但不会改变订阅结果。管理员开启“超限后自动暂停”后，Nginx 按 Token 即时执行分钟频率限制，后台每 30 秒检查 24 小时跨 IP 用量；暂停中的请求返回 `429`，可以在安全状态页提前解除。显式 IP 白名单会跳过这两项限制。

风险预警与自动执行保持独立：只有两层同时启用时，系统才要求“单 Token / 分钟预警”低于“每分钟拉取硬上限”。严格、均衡和宽松预设会根据当前硬上限自动收敛分钟预警值，前端即时提示冲突，保存接口也会拒绝倒挂配置。

`token_limit_state.json` 和后台 API 只保存/返回 HMAC 指纹、计数、原因与解封时间，不保存 Token 明文；为了让 Nginx 能精确匹配，运行时 `token_limit.conf` 仅保存当前暂停 Token 的匹配规则，不会显示在后台或导出数据中。

当前用量会同时显示“24 小时请求/IP 总量”和“规则周期 IP/峰值”。管理员解除暂停后，24 小时历史仍保留用于调查，但新的限制周期从解除时间重新计数，避免把历史总量误显示为再次超限。

点击 Token 指纹或“调查”可打开调查档案：汇总最近 24 小时的请求次数、独立 IP、ASN、客户端类型、异常证据、来源情报和最近事件，并可跳转到对应拉取记录或执行人工拉黑。调查只读取网关日志与现有 IP 情报缓存，不连接机场数据库；Token 明文仅在已登录管理员主动打开具体档案时按需返回，不进入安全总览与缓存摘要。

Token 限制配置使用原子写入和原子备份，生成文件统一为 `www-data:www-data`、权限 `0660`。这避免后台保存与 root 身份维护任务交替运行时把配置变成 PHP-FPM 不可读，导致 `cannot backup token_limit.conf`。

SubSieve 保持独立网关边界，不连接机场用户、邮箱、订单、套餐或节点数据库。因此邮箱封禁、付费账号识别、订单金额、用户历史、自动节点同步和低流量付费画像没有移植；可信节点/落地 IP 请使用 IP 白名单维护。

## 拦截层说明

订阅请求按以下优先级过滤，通过全部拦截后才反代到机场后端：

1. **黑名单**：IPv4/CIDR 封禁，nginx `deny` 返回 403
2. **可疑 UA / 自定义封禁 UA**：空 UA、curl、wget、python、Go、Java 或管理员添加的关键词返回 403
3. **UA 白名单**：只豁免上一项 UA 规则，不能绕过云厂商 IP、Token 黑名单或 Token 临时暂停
4. **云厂商 IP**：通过厂商公开网段或 ASN 宣告前缀识别 26 家云服务商 / IDC；现有 10 家默认沿用启用，其余默认关闭并可逐家开启，命中后返回 403
5. **Token 黑名单**：命中封禁 Token 返回 403
6. **Token 拉取限制**：自动暂停开启后，超出每分钟频率或 24 小时独立 IP 上限的 Token 返回 429
7. **IP 白名单**：跳过云 IP、UA、Token 黑名单、Token 临时暂停和 Token 频率限制；显式 IP 黑名单仍然生效
8. **全局 IP 速率限制**：每分钟 20 次，burst 5，超出返回 429

云厂商 IP 库每周自动更新，候选配置通过 nginx 语法检查后才会替换并重载；校验或重载失败会恢复上一版。首次升级会从旧的合并规则拆分厂商缓存，外部数据源短暂失败时继续沿用上一版 CIDR。浪潮云、移动云因目录暂未配置可验证的 ASN/CIDR 来源，只展示识别关键词且开关保持不可用，避免产生“已开启但实际不拦截”的假状态。更新日志见容器内 `/var/log/subscribe/update_cloud_geo.log`。

部署主机可运行 `bash sgw/tests/runtime_idc_block.sh` 做无真实 Token 的 IDC 运行时自检；运行 `bash sgw/tests/runtime_token_limit.sh` 可在隔离端口验证 Token 频率规则前 10 次放行、第 11 次返回 429。两个测试都不会访问机场后端。

脚本/扫描器报告中的 IP 情报由后台预热任务通过 `ip-api`、`ipwho.is`、`GeoJS` 和 `RIPEstat` 多源查询：前三者交叉验证国家、地区、城市、ASN 与运营商，`RIPEstat` 补充 BGP 宣告 ASN 和路由网段；报告会展示来源数量、一致性和置信度。网页请求本身不会等待外部接口，每轮最多补全 5 个新 IP；`ipwho.is` 设有每日调用预算并预留余量。结果按来源完整度和置信度缓存 6 小时至 7 天，失败结果 10 分钟后重试；单个来源不可用时仍会合并其他可用结果并缩短重查周期。

拉取记录复用同一份 IP 情报缓存。当前页缺失或过期的公网 IP 会进入后台查询队列，由每分钟预热任务优先补全，每轮最多 5 个；页面保持先显示日志、后异步补充情报。每条记录还提供 `ipwho.is`、`RIPEstat` 和 `IPYard` 外部核验入口，其中 IPYard 为网页查询入口，打开时会同时复制当前 IP，方便直接粘贴复核。IP 风险仅表示代理、VPN、Tor、机房/托管和多源一致性信号，不会单独触发自动封禁。

后台容器启动后会每分钟自动预热分析统计缓存，写入 `/etc/nginx/subscribe/stats_cache.json`。分析页默认读取缓存，避免日志量增长后每次打开页面都扫描大日志；首次部署和后续更新都会自动启用，无需手动配置。当前统计默认基于最近 30000 行网关日志生成。

### 告警推送与历史

告警推送默认关闭，可在后台「系统设置 → 告警推送」中开启。后台维护任务每分钟读取统计缓存，发现脚本/扫描器拉取订阅、可疑 IP、多 IP 拉取同一 Token 等高危事件时推送。

- **推送渠道**：支持 Webhook 和 Telegram；建议先用「测试推送」确认渠道可用。
- **规则与去重**：可调整扫描器评分、可疑 IP 评分、Token 被多少个 IP 拉取才告警、同一事件去重分钟数和历史保留条数，也可套用「严格 / 均衡 / 安静」预设。
- **静默时段**：静默期间命中的事件会写入历史并计入去重，但不会外发 Webhook / Telegram；后台会显示最近静默摘要、历史状态分布和历史覆盖时间。
- **手动巡检**：点击「立即检查」可立刻执行一次高危事件巡检；如需重新推送同一事件，可点击「重置去重」。
- **历史查看**：最近记录支持 10 / 25 / 50 条分页、首页/末页/页码跳转、状态筛选、时间范围筛选、关键词搜索、防抖搜索、Enter 搜索、Esc/按钮清空、筛选摘要标签和一键重置。
- **复制与导出**：单条记录、当前页、当前页摘要均可复制；当前页 JSON 和全量历史 JSON 均可导出。复制文本和当前页 JSON 会包含筛选条件、页码范围和记录范围，当前页导出文件名也会带状态、时间范围和页码。
- **导入与迁移**：导入兼容全量历史和当前页导出文件。导入前会预览文件名、文件大小、导出时间、条数、状态分布、时间范围、来源筛选和来源关键词；旧备份、未来导出时间或空记录文件会额外提示。导入只替换展示历史，不修改告警配置和去重状态，成功后自动回到全部状态、全部时间、第 1 页查看结果。
- **移动端体验**：搜索区会自动换行，列表操作按钮会下沉为更易点击的双按钮布局。

告警去重状态保存在 `/etc/nginx/subscribe/alert_state.json`，最近检查状态和推送历史保存在 `/etc/nginx/subscribe/alert_history.json`。

后台容器还会定时清理旧访问日志，默认保留最近 14 天，避免 `access.log` 长期增长拖慢统计或占满磁盘。如需调整，可在 `sgw/.env` 中设置：

```env
LOG_RETENTION_DAYS=14
```

设为 `0` 可关闭自动清理。维护日志见容器内 `/var/log/subscribe/maintenance.log`。

## 常用命令

```bash
# 查看实时日志
docker logs -f subscribe-gateway
docker logs -f subscribe-admin

# 重启服务
docker compose restart

# 完整重建
docker compose up -d --build

# 检查分析统计缓存是否在自动更新
docker exec subscribe-admin sh -lc 'ls -lh /etc/nginx/subscribe/stats_cache.json'

# 检查 gateway / admin 容器健康状态，异常时自动显示最近日志
bash healthcheck.sh --wait 30

# 查看后台维护任务日志（统计预热 / 告警检查 / 日志清理）
docker exec subscribe-admin sh -lc 'tail -50 /var/log/subscribe/maintenance.log'

# 进入 gateway 容器调试
docker exec -it subscribe-gateway sh
```
